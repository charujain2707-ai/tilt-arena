# Tilt Arena – Anything but a Game Controller

**play live game:**https://tilt-arena.onrender.com
open the link through laptop, scan the QR with mobile phone.

Turn your phone into a real-time motion controller for a browser game on your laptop.
Tilt to roll your ball, grab stars, shake (or tap **Jump**) to hop over holes. First to 10 wins. Up to 8 phones can play together.

**Live demo:** `https://<your-app>.onrender.com` (replace after deploying)

## Features
| Requirement | How it's done |
|---|---|
| Gyroscope + accelerometer → controls | `deviceorientation` (gyro + accelerometer fused by the phone) gives tilt → steering. `devicemotion` linear acceleration > 13 m/s² = shake → jump. Gyro rotation rate shown live on the phone. |
| Pairing via QR or room code | Laptop gets a 4-character room code and a QR code (generated by the server at `/qr.svg`). Scanning opens the controller with the code pre-filled. |
| Streaming over WebSockets | Phone → server → laptop relay using `ws`, one room per laptop. |
| Simple browser game | Canvas ball-balancing arena with holes, stars, jumping, boosting and ball-to-ball bumps. |
| Calibration | Auto-calibrates on start; **Calibrate** button sets the current pose as neutral. Dead-zone stops drift. |
| Connection status + auto-reconnect | Status light on both devices. Exponential back-off reconnect, heartbeat that detects silent drops in 4 s, reconnect on returning to the tab, rooms survive a laptop refresh, players keep their colour and score when they reconnect. |
| **Bonus** | Local multiplayer (8 phones), on-screen Jump/Boost buttons, vibration feedback (stars, falls, win), live latency on both devices. |

## Tech stack
- **Server:** Node.js, `http` + [`ws`](https://github.com/websockets/ws), `qrcode`
- **Game:** HTML5 Canvas + vanilla JS (`public/game.html`, `public/game.js`)
- **App:** Installable web app / PWA (`public/controller.html`, `controller.js`, `manifest.json`, `sw.js`). Packaged as an Android APK with PWABuilder.

```
server.js            WebSocket relay + static files + QR endpoint
public/game.*        laptop game (host)
public/controller.*  phone controller (app)
```

## Latency approach
- Sensor packets are tiny (`{"t":"s","x":0.42,"y":-0.1}`), sent once per screen frame (~60 Hz) and only when the value changes (plus a 200 ms keep-alive).
- **Compression off** (`perMessageDeflate: false`) and **Nagle off** (`setNoDelay`) so nothing waits in a buffer.
- If the socket backs up (`bufferedAmount`), the phone drops that frame instead of queueing it – old input is worse than missing input.
- The server only forwards messages, no processing.
- The game applies a very light smoothing (~30 ms) to hide network jitter without adding noticeable lag.
- Latency is measured end-to-end every second (phone → server → laptop → phone) and shown on both screens.

## Pairing flow
1. Laptop opens `/game.html` → server creates room `ABCD`, laptop shows code + QR.
2. Phone scans QR → `/controller.html?room=ABCD` → taps **Connect and play** (needed for iOS motion permission).
3. Phone sends `join {room, id, name}`; the `id` is stored on the phone so reconnects rejoin the same player.

## Run locally
```bash
npm install
npm start          # http://localhost:3000
```
Phones need **https** for motion sensors, so test with the deployed link.

## Deploy (free, https) on Render
1. render.com → sign in with GitHub → **New → Web Service** → pick this repo.
2. Build command `npm install`, start command `npm start`, instance type **Free** → Create.
3. Open the `.onrender.com` URL on the laptop. (Free instances sleep after ~15 min idle; the first load can take up to a minute.)

## APK
pwabuilder.com → paste `https://<your-app>.onrender.com/controller.html` → **Package for stores → Android** → download the APK.
